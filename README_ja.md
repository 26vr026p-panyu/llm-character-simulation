# LLM Interactive Character Simulation

[English](README.md) | [简体中文](README_zh-CN.md)

LLMによる対話生成と、決定論的なゲーム状態管理・段階制御・ローカルフォールバック（API未使用時・失敗時の固定応答）を組み合わせたインタラクティブナラティブのプロトタイプです。

## 概要

**PAN YU**によるPython/Gradioのプロトタイプです。大学生活を舞台にしたキャラクター関係シミュレーションとして実装し、生成AIによるキャラクター表現と明示的なゲームルールの両立を試しています。プレイヤーは行動候補または自由入力で会話を進めます。

**Pythonが好感度・警戒・進行・結末を管理し、LLMは物語と行動候補を生成します。** 親密な行動には別途Pythonの確率判定があるため、実行全体は決定的ではありません。

明示的な状態と進行ルールの中で行動を生成する、軽量なキャラクターエージェント構成の試作でもあります。完全な自律型エージェントではなく、ツール呼び出し・計画と実行を分担する仕組み・外部ツール連携はありません。Unity連携は今後の構想です。

## 技術的な見どころ

- **役割の分離：** Pythonが数値状態と進行を管理し、LLMは物語表現を担当。
- **段階に応じた制約：** プロンプトと候補フィルタで早すぎる展開を抑制。
- **生成失敗への対応：** JSON解析・出力確認とローカルフォールバックで操作を継続。
- **セッション状態の復元：** スナップショットのコピーにより1回の巻き戻しを実現。
- **実行時の保護：** HTMLエスケープとプロジェクト単位の秘密情報読込。

## システム構成 — LLMとゲームロジックの分担

```text
プレイヤーの行動 → Gradio → Pythonのキーワード判定
                                   ↓
                      好感度・警戒・親密行動の確率判定
                                   ↓
                          Pythonの段階更新
                                   ↓
         状態・履歴・記憶 → DeepSeekの物語と選択肢（またはローカルフォールバック）
                                   ↓
                   JSON解析・本文確認・行動候補の整形
                                   ↓
                  記憶と統計の更新 → HTMLエスケープ → UI
                                   ↓
                     Pythonが結末を選択し固定文を表示
```

**設計原則：** LLMは物語と行動候補を生成しますが、好感度・警戒・進行段階・結末を直接書き換えることはできません。

| 担当 | app.py内の実装 |
| --- | --- |
| 行動の採点 | 日本語キーワード判定、`calculate_love_change` |
| 親密行動の成否 | `judge_romance_success`、Pythonの乱数 |
| 進行・結末 | `advance_stage`、`is_end_stage`、`make_ending_story` |
| キャラクター表現 | `make_system_prompt`、`call_ai`、`deepseek-chat` |
| 出力確認 | `clean_json_text`、型確認、`is_bad_story_text`、`normalize_choices` |
| セッション状態 | `gr.State`、`make_snapshot`、`undo` |

LLMには計算済みの状態を渡します。生成文はキーワードによるイベント記憶の更新に影響します。JSONの`special_action`は現状未使用です。JSONはプロンプトで要求しており、API側の厳密なスキーマ強制ではありません。

## 主な機能

### LLMとのインタラクション

- 日本語の物語と文脈に応じた3つの行動候補、プレイヤーの自由入力。
- 4つの初期イベントまたは自由なテーマ入力、固定のキャラクター設定。
- 段階・セッション内の履歴・イベント記憶を生成時に参照。記憶は最大8件を保持し、4件を表示。

### ゲーム状態の管理

- 好感度、警戒と関係修復、5段階の進行、5種類の終了状態。
- 親密行動の確率判定、スナップショットによる1回の巻き戻し。
- 好感度の表示切替、関係変化の通知、行動統計。

### 信頼性を支える処理

- キー未設定・生成失敗時のローカルフォールバック。
- JSON解析、本文の検証、行動候補の整形。
- HTMLエスケープとプロジェクト単位の秘密情報読込。

## 技術的なポイント

- **生成前にルールを実行：** キーワード採点とPythonの親密行動判定で状態を更新してから、モデルに文脈を渡します。結末の選択と結末文の表示もPythonが担当します。
- **出力の制約：** 段階別プロンプトで状況を伝え、JSON解析・型と本文の確認・候補の整形で不適切な出力を除外または補完します。API側の厳密なJSONスキーマ強制ではありません。
- **失敗後も操作を継続：** 通信や解析に失敗した場合は、採点ルールを変えずにローカルフォールバックの文章と標準候補を使います。
- **状態の復元：** Gradioのセッション状態に加え、イベント記憶や入れ子の統計をコピーしたスナップショットで1回の巻き戻しを支えます。
- **表示と設定の保護：** 独自HTMLの文字列をエスケープし、ローカル限定で起動します。.envはapp.pyの隣だけを読み込み、エラーログには例外の詳細を出しません。

## ゲームの流れ

設定 → 初回の共同作業 → 二回目の共同作業 → 作業後の雑談 → 二人で過ごす時間 → 関係の確認 → 結果。

Pythonが自己紹介の有無・ターン数・好感度から段階と結末を決めます。警戒状態は対話や関係修復に影響し、LLMは更新後の状態を物語と行動候補として表現します。

## 技術スタック

Python、Gradio、python-dotenv、OpenAI Python SDK、**DeepSeek API**（`deepseek-chat`）。

OpenAI Python SDKはAPI互換クライアントとして使用しています。OpenAI提供のモデルやGeminiは使用していません。

## セットアップ

開発環境で見つかった依存バージョンを固定しています。検証環境はPython 3.14です。他バージョンでの動作は未保証です。

リポジトリのディレクトリからWindows PowerShellで実行します。

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
# 必要に応じて.envのDEEPSEEK_API_KEYを設定
python app.py
```

有効化スクリプトが使えない場合は、`.\.venv\Scripts\python.exe`でpipとapp.pyを直接実行できます。コマンドプロンプトでは`.venv\Scripts\activate.bat`で有効化します。

端末に表示されたURL（通常 http://127.0.0.1:7860 ）を開きます。終了はCtrl+Cです。元の開発ディレクトリや外部素材は不要です。

.envもプロセス環境のキーもない場合、UIとルールは動作しますが、文章・選択肢は簡易なローカルフォールバックになります。生成機能には有効なDeepSeekキー、ネット接続、API残高が必要です。認証エラーでもローカルフォールバックに切り替わるため、画面が動くだけではAPI成功を確認できません。

まずは`課題発表`を選んで開始し、`丁寧に自己紹介する`と入力してください。`好感度を表示する`で変化を確認し、おすすめの行動や1回の巻き戻しも試せます。

## 環境変数

```dotenv
DEEPSEEK_API_KEY=
```

アプリ独自の設定変数はこれだけです。app.pyと同じ場所の.envよりプロセス環境変数を優先します。実際のキーをコミットしないでください。API利用時は主人公名、テーマ、行動、物語履歴、イベント記憶をDeepSeekへ送信するため、デモには架空の情報を使用してください。

## 制約と今後の改善

部分一致による採点なので、否定や微妙な表現を誤判定する場合があります。親密行動に乱数を使うため、実行全体は決定的ではありません。プロンプトと簡易フィルタだけで物語の整合性を保証することはできません。履歴のトークン上限管理やセッションをまたぐ保存は未実装です。巻き戻しでは乱数状態や生成済みの選択肢までは復元しません。性格タイプ表示はゲーム内の簡易集計で、心理評価ではありません。

今後は履歴長の制御、出力検証の強化、シナリオ追加、Unityによるキャラクター表現を検討できます。現時点でアニメーション・音声・データベース・永続記憶はありません。
